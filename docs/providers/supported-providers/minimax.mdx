## Overview

MiniMax is an OpenAI-compatible provider with its own Bifrost implementation. Chat goes through the shared OpenAI converters. Image and video generation use MiniMax's native endpoints, which Bifrost maps to the standard image and video APIs. Key characteristics:

- **OpenAI-compatible chat.** Chat Completions use `/v1/chat/completions`.
- **Reasoning.** Bifrost asks MiniMax to split thinking into `reasoning_content`, so it never shows up as `<think>` tags inside the answer.
- **Tool calling.** Function tools use the OpenAI-compatible schema.
- **Vision.** `MiniMax-M3` and `MiniMax-M3.1-Flash-Preview` accept `image_url` parts. The M2.x models are text only.
- **Responses API.** Sent to MiniMax's native `/v1/responses`.
- **Anthropic Messages.** `/anthropic/v1/messages` requests for a MiniMax model are forwarded unchanged to MiniMax's Anthropic-compatible `/anthropic/v1/messages`.
- **Image generation.** `image-01` through `/v1/image_generation`.
- **Video generation.** `MiniMax-H3` and `MiniMax-H3-Max` as async tasks through `/v2/video_generation`.
- **Text-to-speech.** `speech-2.8-hd`, `speech-2.8-turbo` and older speech models through `/v1/t2a_v2`, streamed or not.
- **Speech-to-text.** `asr-1.0` through `/v1/speech_to_text`, with sentence or word timestamps, speaker labels, SRT/VTT output and streaming.
- **Text completions (txehq/bifrost fork).** `/v1/completions` requests go to MiniMax's Anthropic-compatible text generation endpoint, `/text/v1/messages` on the base URL's origin, streamed or not. See [Text completions](#text-completions).

## Video generation

MiniMax has two video APIs, and Bifrost picks one by model (fork, TXE-6428):

- **v2** (`MiniMax-H3`, `-Highspeed`, `-Lite`, `-Max`): `seconds` (4 to 15, 5 to 15 on H3-Max) becomes `duration`, `resolution` (`480P`, `768P`, `2K`) and `aspect_ratio` (`ratio`) are sent as given, and `last_frame` and `reference_images` become content items. A `size` must be exactly one tier at one ratio, as the task reports it (`1365x768` is 768P at 16:9); otherwise send `resolution` and `aspect_ratio`. With no `aspect_ratio` Bifrost sends no ratio, and MiniMax applies `adaptive`. The query returns `usage.output_seconds`, `input_seconds`, `input_images` and `output_tokens`, the raw status in `provider_status`, and `cancelled` as its own status. MiniMax states no lifetime for the v2 video URL, so `expires_at` is not set.
- **v1** (`MiniMax-Hailuo-2.3`, `-2.3-Fast`, `-02`): `seconds` (6 or 10), `resolution`, `input_reference` (`first_frame_image`) and `last_frame` (`last_frame_image`) are sent to `/v1/video_generation`; `size`, `aspect_ratio` and `reference_images` are refused. The task id Bifrost returns starts with `v1-`. A query reads `/v1/query/video_generation` and, once the task succeeded, `/v1/files/retrieve` for the download URL, which lives one hour: `expires_at` is the file's creation time plus one hour. MiniMax reports no usage for v1 tasks. v1 has no cancel or delete API.

`callback_url` is forwarded unchanged on both. `seed`, `audio`, `client_reference_id`, `expires_after_seconds` and `output_storage_uri` cannot reach MiniMax and are refused with 400 `caller_unsupported_parameter`; an out-of-range value is refused, never clamped. Extra fields are merged into the body, so MiniMax options such as `extra.prompt_expansion_mode` (H3-Max) and `prompt_optimizer` (v1) arrive unchanged.

`POST /v1/videos/{id}/cancel` queries the v2 task first and sends `DELETE` only while it is `queued`, because MiniMax's `DELETE` deletes a finished task. Any other state returns 400 `provider_cancel_unsupported` without a `DELETE`.

## Text completions

This fork serves text completions, which upstream Bifrost reports as unsupported for MiniMax. The prompt is sent as an Anthropic messages request to `/text/v1/messages` on the base URL's origin, with `anthropic-version: 2023-06-01`, and the reply is returned in the text completion shape. Streaming uses the provider's streaming connection, so a long stream is bounded by the stream idle timeout rather than the request timeout.

For prompt caching on this endpoint, pass `anthropic_beta` in `extra_params`. Bifrost forwards it as the `anthropic-beta` header:

- String form: `"anthropic_beta": "prompt-caching-2024-07-31"`
- Array form: `"anthropic_beta": ["prompt-caching-2024-07-31", "..."]`

## Setup and configuration

Bifrost calls `https://api.minimax.io` by default. Both pay-as-you-go API keys and M Plan subscription keys work, since MiniMax sends both as a bearer token. For the mainland China platform, set `network_config.base_url` to `https://api.minimaxi.com`.

# 1. Chat Completions

## Request parameters

MiniMax supports the OpenAI chat parameters it documents: `max_completion_tokens`, `temperature` (0 to 2), `top_p`, `tools`, `stream`, `stream_options` and `service_tier`. For the full parameter reference, see [OpenAI Chat Completions](/providers/supported-providers/openai#1-chat-completions).

Current text models are `MiniMax-M3`, `MiniMax-M3.1-Flash-Preview` (M Plan only), `MiniMax-M2.7`, `MiniMax-M2.5` and `MiniMax-M2.1`, plus `-highspeed` variants of the M2.x models. MiniMax closes M2.5 and M2.7 to new users on October 19, 2026 and retires them on November 18, 2026.

```bash
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "minimax/MiniMax-M3",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

### Reasoning

Bifrost sends `reasoning_split: true` on every chat request, so MiniMax returns its thinking in `reasoning_content` and Bifrost exposes it as the message's `reasoning`. If you set `reasoning_split` yourself through extra params, Bifrost leaves it alone.

`reasoning_effort` maps to MiniMax's own values, with two adjustments:

| Bifrost value | Sent to MiniMax |
|---------------|-----------------|
| `minimal` | `low` |
| `low`, `medium`, `high`, `xhigh`, `max` | unchanged |
| `none` | `thinking: {"type": "disabled"}` and no `reasoning_effort` |
| `none` on `MiniMax-M3.1-Flash-Preview` | nothing; the model always thinks and rejects both `none` and `disabled` |

The M2.x models ignore `thinking.type: disabled`, so they keep thinking either way.

### Extra parameters

Extra parameters pass through, so MiniMax-only fields like `thinking`, `service_tier` or `reasoning_split` reach the API unchanged.

### Content-safety flags

MiniMax reports whether its content filter fired on every chat response, and Bifrost returns those fields unchanged at the top level of the chat response, streamed or not (on a stream, the final chunk carries the complete set):

| Field | Type | Meaning |
|-------|------|---------|
| `input_sensitive` | boolean | The input contained sensitive content |
| `output_sensitive` | boolean | The output contained sensitive content |
| `input_sensitive_type` | integer | `1` severe violation, `2` pornography, `3` advertising, `4` prohibited, `5` abusive, `6` terrorism/violence, `7` other; `0` when nothing fired |
| `output_sensitive_type` | integer | The same codes for the output |

Providers that do not report these fields leave them out.

### Errors

MiniMax sometimes returns HTTP 200 with a non-zero `base_resp.status_code`. Bifrost turns those into errors with a matching HTTP status. For example, `1002` becomes 429, `1004` becomes 401, `1008` (insufficient balance) becomes 402, and `1026`/`1027` (sensitive content) become 400.

# 2. Responses API

Responses API requests go to MiniMax's OpenAI Responses-compatible `POST /v1/responses`, streamed or not, with the same Bearer key as chat. MiniMax returns the Responses shape itself (`output` items of type `reasoning`, `message` and `function_call`; `usage.input_tokens`, `output_tokens`, `input_tokens_details.cached_tokens`, `output_tokens_details.reasoning_tokens`), and streams `response.*` SSE events. A non-zero `base_resp.status_code` on a 200 is an error, as on chat.

# 2a. Anthropic Messages

MiniMax serves an Anthropic-compatible API at `https://api.minimax.io/anthropic`. A `/anthropic/v1/messages` request whose model is a MiniMax model (`minimax/MiniMax-M3`) is forwarded to `/anthropic/v1/messages` on the base URL's origin byte for byte, apart from the `minimax/` prefix taken off `model`, with `Authorization: Bearer <key>`. MiniMax's response, streamed or not, is returned unchanged. MiniMax documents which Anthropic parameters it honours and which it ignores.

# 4. Image Generation

`image-01` generates up to 9 images per request.

```bash
curl -X POST http://localhost:8080/v1/images/generations \
  -H "Content-Type: application/json" \
  -d '{
    "model": "minimax/image-01",
    "prompt": "A lighthouse at dusk, oil painting",
    "n": 2,
    "size": "1024x1024"
  }'
```

| Bifrost parameter | MiniMax field | Notes |
|-------------------|---------------|-------|
| `prompt` | `prompt` | Up to 1500 characters |
| `n` | `n` | 1 to 9 |
| `size` | `width` + `height` | When both sides are 512 to 2048 and divisible by 8. Otherwise Bifrost picks the closest supported aspect ratio. |
| `aspect_ratio` | `aspect_ratio` | `1:1`, `16:9`, `4:3`, `3:2`, `2:3`, `3:4`, `9:16`, `21:9`. Takes priority over `size`. |
| `response_format` | `response_format` | `b64_json` becomes `base64`. MiniMax image URLs expire after 24 hours. |
| `seed` | `seed` | |
| `extra_params.prompt_optimizer` | `prompt_optimizer` | |

If content safety blocks every image, the request fails with a 400 instead of returning an empty list.

# 5. Video Generation

MiniMax video generation is asynchronous. Create a task, poll it, then download the result.

```bash
curl -X POST http://localhost:8080/v1/videos \
  -H "Content-Type: application/json" \
  -d '{
    "model": "minimax/MiniMax-H3",
    "prompt": "A paper boat drifting down a rainy street",
    "seconds": "6",
    "size": "1280x720"
  }'
```

| Operation | Endpoint | Notes |
|-----------|----------|-------|
| Create | `POST /v1/videos` | Returns a queued job ID |
| Get status | `GET /v1/videos/{id}` | Poll until `status: completed`. MiniMax keeps tasks for 7 days. |
| Download content | `GET /v1/videos/{id}/content` | Fetches the MP4 from the signed URL on the task |
| Cancel or delete | `DELETE /v1/videos/{id}` | Cancels a queued task or deletes a finished one |

## Parameter mapping

| Bifrost parameter | MiniMax field | Notes |
|-------------------|---------------|-------|
| `prompt` | `content[]` text item | Required |
| `input_reference` | `content[]` image item with role `first_frame` | Image to video |
| `seconds` | `duration` | Defaults to 6. Clamped to 4 to 15 on `MiniMax-H3` and 5 to 15 on `MiniMax-H3-Max`. |
| `size` | `resolution` + `ratio` | The short side picks the tier (`480P` only on H3-Max, `2K` only on H3 above 1080 pixels, otherwise `768P`) and the shape picks the closest ratio. |
| `resolution` | `resolution` | Unified field. Overrides the tier derived from `size`. |
| `aspect_ratio` | `ratio` | Unified field. Overrides the ratio derived from `size`. MiniMax's own name, `ratio`, is accepted as an extra parameter only together with `aspect_ratio` and the same value. |
| `last_frame` | `content[]` image item with role `last_frame` | |
| `reference_images` | `content[]` image items with role `reference_image` | Can't be combined with first or last frame images |
| `callback_url` | not sent | A task control field. Refused with `400` `caller_unsupported_parameter`, as a request field or as an extra parameter, because this provider does not declare it. |

`aspect_ratio`, `resolution`, `last_frame` and `reference_images` are unified request fields: send them as the request's own fields. Naming one only among the extra parameters is refused with `400` `caller_unsupported_parameter`, because a field that affects the price must be visible on the request. Go SDK callers set the field on `Params` and keep the same value in `ExtraParams`, where this provider's converter reads it; the HTTP routes do that for you.

Without a `size`, text to video uses `16:9` (MiniMax needs a concrete ratio there) and image to video uses `adaptive`. `video_uri` and video list aren't supported.

# 6. Speech (TTS)

```bash
curl -X POST http://localhost:8080/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{
    "model": "minimax/speech-2.8-turbo",
    "input": "Hello! This is MiniMax speaking through Bifrost.",
    "voice": "English_Graceful_Lady",
    "response_format": "mp3"
  }' --output hello.mp3
```

`voice` is a MiniMax `voice_id`, such as `English_Graceful_Lady`, `English_Insightful_Speaker` or `English_Persuasive_Man`, or a cloned or designed voice. See MiniMax's [system voice list](https://platform.minimax.io/docs/faq/system-voice-id) for the rest. MiniMax reports an unknown voice as an HTTP 200 with error code 2054 (`voice id not exist`), and Bifrost returns it as a 400.

| Bifrost parameter | MiniMax field | Notes |
|-------------------|---------------|-------|
| `input` | `text` | Under 10,000 characters |
| `voice` | `voice_setting.voice_id` | Required. Multi-speaker voice config isn't supported. |
| `speed` | `voice_setting.speed` | 0.5 to 2 |
| `response_format` | `audio_setting.format` | `mp3` (default), `wav`, `flac`, `pcm`, `opus`, `pcmu_raw`, `pcmu_wav`. Other formats are rejected. |
| `extra_params.vol`, `extra_params.pitch`, `extra_params.emotion` | `voice_setting.vol`, `.pitch`, `.emotion` | |
| `extra_params.sample_rate`, `extra_params.bitrate`, `extra_params.channel` | `audio_setting.*` | |
| `extra_params.language_boost` | `language_boost` | For example `English` or `Chinese,Yue` |

Any other extra params, such as `pronunciation_dict` or `voice_modify`, are sent to MiniMax unchanged. Usage reports MiniMax's `usage_characters`.

## Streaming

Set `stream_format: "sse"` on `/v1/audio/speech` to stream. MiniMax returns hex-encoded audio chunks, which Bifrost decodes into `speech.audio.delta` events, followed by a `speech.audio.done` event carrying usage. Bifrost asks MiniMax not to repeat the whole clip in its final chunk (`exclude_aggregated_audio`), so each audio byte arrives once.

# 7. Transcriptions (STT)

```bash
curl -X POST http://localhost:8080/v1/audio/transcriptions \
  -F model="minimax/asr-1.0" \
  -F file="@meeting.mp3" \
  -F language="en" \
  -F response_format="verbose_json" \
  -F "timestamp_granularities[]=word"
```

| Bifrost parameter | MiniMax field | Notes |
|-------------------|---------------|-------|
| `file` | `file` | wav, aiff, flac, m4a, mp3, aac, opus, ogg. Up to 500 seconds and 50 MB. |
| `language` | `language` request header | Short codes such as `en`, `zh`, `ja`. Omit it for mixed-language audio. |
| `response_format` | `response_format` | `json` (default), `verbose_json`, `srt`, `vtt`. `text` is served from MiniMax's `json` output. |
| `timestamp_granularities` | `timestamp_level` | `segment` maps to `sentence` and `word` to `word`. Either one switches the response to `verbose_json`. |

With `verbose_json`, sentence-level timestamps come back as `segments`. Word-level timestamps come back as `words`, with MiniMax's speaker label (`S1`, `S2`, and so on) on each word. Usage is reported as seconds of audio.

## Streaming

Send the form field `stream=true` to stream. Each MiniMax event becomes a `transcript.text.delta`, and the final event becomes `transcript.text.done` with the full text and the audio duration. When the final MiniMax event carries text of its own, that text arrives first as one more `transcript.text.delta`, so the deltas always add up to the full transcript. MiniMax only streams the `json` format, so streaming with `verbose_json`, `srt` or `vtt` fails with a 400.
