## Overview

The `dashscope` provider is Alibaba Cloud Model Studio's native DashScope API, which serves Wan video, Qwen-Image and Z-Image images, Qwen3-TTS speech and Qwen3-ASR transcription. Qwen chat stays on the [`qwen`](/providers/supported-providers/qwen) provider, which speaks DashScope's OpenAI-compatible mode.

<Note>
Wan video is implemented: create, query, list, cancel and download. Image generation and edit with Qwen-Image and Z-Image are served, and so are speech (Qwen3-TTS) and transcription (Qwen3-ASR), non-streamed. Every other operation returns `UnsupportedOperationError` (HTTP 400, `error.code` `unsupported_operation`) without calling DashScope. Wan images and streamed speech are added in later releases.
</Note>

### Supported Operations

| Operation | Non-Streaming | Streaming | Base |
|-----------|---------------|-----------|------|
| Video create, query, list, cancel, download (Wan) | ✅ | - | `workspace_base_url` |
| Video delete, remix, edit | ❌ | - | - |
| Image generation (Qwen-Image, Z-Image) | ✅ | ❌ | `base_url` |
| Image edit (Qwen-Image) | ✅ | ❌ | `base_url` |
| Wan images (task-based) | ❌ (planned, on the image task routes) | - | `base_url` |
| Speech (Qwen3-TTS) | ✅ | ❌ | `base_url` |
| Transcription (Qwen3-ASR) | ✅ | ❌ | `workspace_base_url` |
| Chat, Responses, Text Completions | ❌ (use `qwen`) | ❌ | - |
| Embeddings, Files, Batch, List Models, everything else | ❌ | ❌ | - |

## Setup & Configuration

The provider has two bases:

- `network_config.base_url` is the regional DashScope site. It defaults to the Singapore (international) site, `https://dashscope-intl.aliyuncs.com`.
- `network_config.workspace_base_url` is your Model Studio workspace address, `https://{WorkspaceId}.ap-southeast-1.maas.aliyuncs.com`. Video and transcription use it. When it is unset they use `base_url`.

Both are checked the same way when written through the management API: no credentials, query or fragment in the URL, an authenticated admin session when dashboard auth is bypassed, and no private-network destination unless `allow_private_network` is set.

## Wan video

A Wan video is an asynchronous task. Each route makes one call to DashScope: Bifrost does not retry, poll or store the task.

| Route | DashScope call |
|-------|----------------|
| `POST /v1/videos` | `POST /api/v1/services/aigc/video-generation/video-synthesis` with `X-DashScope-Async: enable` |
| `GET /v1/videos/{id}` | `GET /api/v1/tasks/{task_id}` |
| `POST /v1/videos/{id}/cancel` | `POST /api/v1/tasks/{task_id}/cancel` |
| `GET /v1/videos/{id}/content` | `GET /api/v1/tasks/{task_id}`, then the task's `video_url` without the key |

### Request fields

The request shape depends on the model family, which Bifrost reads from the model name. A model outside these families (for example HappyHorse) returns 400 with `error_type` `caller_model_unknown` and is not sent.

| Unified field | Wan 3.0 (`wan3.0-*`) | Wan 2.7 (`wan2.7-*`) | Wan 2.6 and earlier (`wan2.6-*`, `wan2.5-*`, `wan2.2-*`, `wan2.1-*`) |
|---------------|----------------------|----------------------|----------------------------------------------------------------------|
| `prompt` | `input.prompt` | `input.prompt` | `input.prompt` |
| `negative_prompt` | `input.negative_prompt` | `input.negative_prompt` | `input.negative_prompt` |
| `input_reference` (first frame) | `input.media[]` `first_frame` | `input.media[]` `first_frame` | `input.img_url` |
| `last_frame` | `input.media[]` `last_frame` | `input.media[]` `last_frame` | 400 |
| `reference_images` | `input.media[]` `reference_image`, in order | 400 | 400 |
| `resolution` (`720P`, `1080P`, ...) | `parameters.resolution` | `parameters.resolution` | `parameters.resolution` with a first frame; 400 without one |
| `aspect_ratio` | `parameters.ratio` | `parameters.ratio` for text-to-video; 400 with a first frame | 400 |
| `size` (`1280x720`) | 400 | 400 | `parameters.size` as `1280*720` for text-to-video; 400 with a first frame |
| `seconds` | `parameters.duration` | `parameters.duration` | `parameters.duration` |
| `audio` | `parameters.audio` | `parameters.audio` | `parameters.audio` |
| `seed` | `parameters.seed` | `parameters.seed` | `parameters.seed` |

- "400" is `error_type` `caller_unsupported_parameter` with the field in `error.param`, returned before any call to DashScope. Bifrost never drops a field, replaces it or moves a value into range.
- With `x-bf-passthrough-extra-params: true`, an extra param named `input` or `parameters` is merged into the object of that name in DashScope's body. A key Bifrost writes there itself (`input.prompt`, `negative_prompt`, `img_url`, `media`; `parameters.size`, `resolution`, `ratio`, `duration`, `audio`, `seed`, `watermark`, `prompt_extend`) is refused with 400 `caller_unsupported_parameter` naming it, for example `parameters.size`: send the request's own field. Any other nested key travels to DashScope.
- `resolution` is sent in upper case (`720p` becomes `720P`). `seconds` must be a whole number; `5.5` is a 400.
- `size` for Wan 2.6 and earlier must be one of DashScope's documented sizes: `832x480`, `480x832`, `624x624`, `1280x720`, `720x1280`, `960x960`, `1088x832`, `832x1088`, `1920x1080`, `1080x1920`, `1440x1440`, `1632x1248`, `1248x1632`. Which of them one model offers is checked by DashScope. Write it as `WxH` with a lower-case `x`; `1280*720` and `1280X720` are a 400.
- `output_format`, `video_uri` and the four task control fields (`callback_url`, `client_reference_id`, `expires_after_seconds`, `output_storage_uri`) are a 400: DashScope has no parameter for them.
- `watermark` and `prompt_extend` (booleans) go to `parameters`. On Wan 3.0, `reference_videos` and `reference_audios` (arrays of URLs) go to `input.media[]` as `reference_video` and `reference_audio`. Each address is an `http` or `https` URL, or a `data:video/` (`data:audio/`) URL; any other scheme, `oss://` included, is a 400.
- With `x-bf-passthrough-extra-params: true`, any other top-level field is merged into the body sent to DashScope, objects recursively. For example `"parameters": {"shot_type": "multi"}` or `"input": {"audio_url": "https://..."}`.

```bash
curl -X POST http://localhost:8080/v1/videos \
  -H "Content-Type: application/json" \
  -d '{
    "model": "dashscope/wan3.0-video",
    "prompt": "A kitten running on a rooftop under the moonlight",
    "seconds": "5",
    "resolution": "720P",
    "aspect_ratio": "16:9"
  }'
```

### Task object

| Task object field | DashScope field |
|-------------------|-----------------|
| `id` | `output.task_id`, with the `:dashscope` suffix |
| `status`, `provider_status` | `output.task_status`: `PENDING` → `queued`, `RUNNING` → `in_progress`, `SUCCEEDED` → `completed`, `FAILED` → `failed`, `CANCELED` → `cancelled`, `UNKNOWN` → `expired`. `provider_status` is DashScope's string unchanged |
| `created_at`, `completed_at` | `output.submit_time`, `output.end_time`, which DashScope sends in UTC+8 |
| `videos[]` | `output.video_url` as `{"type": "url", "url": ..., "content_type": "video/mp4"}`, the vendor's link unchanged |
| `expires_at` | `submit_time` plus 24 hours: DashScope keeps a task and its link for 24 hours |
| `usage.output_seconds`, `seconds` | `usage.output_video_duration`; for the older families, which do not report it, `usage.video_duration` or `usage.duration`. Absent when DashScope reports none |
| `usage.input_seconds` | `usage.input_video_duration`, only when DashScope reports it |
| `error` | `output.code` and `output.message` of a failed task |
| `content_filter` | Set when a failed task's code is `DataInspectionFailed` or `IPInfringementSuspect` |

DashScope reports `UNKNOWN` for a task older than 24 hours and for a task id it never issued. Both are `expired`.

The create response carries the id and `status` `queued` only. DashScope returns the times, usage and link on a query.

### Cancel

DashScope cancels a task only while it is `PENDING`. For a task in any other state it answers 400 `UnsupportedOperation`, which Bifrost returns as 400 with `error_type` `provider_cancel_unsupported` and DashScope's message. A cancelled task object carries `status` `cancelled` and no `provider_status`, because DashScope's cancel response reports no state.

### List

`GET /v1/videos?provider=dashscope` calls DashScope's task list, `GET /api/v1/tasks`.

| Query parameter | Sent to DashScope as |
|-----------------|----------------------|
| `limit` | `page_size` |
| `page_no`, `start_time`, `end_time`, `model_name`, `status`, and any other DashScope filter | the same name and value, unchanged; a repeated parameter stays repeated |
| `after`, `order` | 400, before any call: DashScope pages by number and has no order parameter |

DashScope pages by number. While there is a further page, the response has `has_more` `true` and `next`, the number of the following page: send it back as `page_no`. `has_more` is read from DashScope's own `page_no` and `total_page`. `start_time` and `end_time` are DashScope's `YYYYMMDDhhmmss`.

```bash
curl "http://localhost:8080/v1/videos?provider=dashscope&limit=20&model_name=wan2.6-t2v&status=SUCCEEDED&page_no=2"
```

Each entry carries `id` (with the `:dashscope` suffix), `model`, `status` by the table above, `created_at` (DashScope's `gmt_create`) and, for a finished task, `completed_at` (`end_time`). DashScope's list has no prompt, size or link: query the task for those. The list is of every asynchronous task of the account in DashScope's 24-hour window, image tasks included; `model_name` narrows it.

## Image generation and edit

`POST /v1/images/generations` and `POST /v1/images/edits` with a `qwen-image-*` or `z-image-*` model call DashScope's synchronous endpoint, `POST {base_url}/api/v1/services/aigc/multimodal-generation/generation`, once. The request becomes one user message: the input images in order, then the prompt.

```bash
curl -X POST http://localhost:8080/v1/images/generations \
  -H "Content-Type: application/json" \
  -d '{
    "model": "dashscope/qwen-image-2.0-pro",
    "prompt": "a lighthouse at dusk",
    "n": 2,
    "size": "1536x1024",
    "negative_prompt": "low quality",
    "prompt_extend": true,
    "watermark": false
  }'
```

| Request field | DashScope field | Notes |
|---------------|-----------------|-------|
| `prompt` | `input.messages[0].content[].text` | |
| `input_images` (generation), `images` (edit) | `input.messages[0].content[].image` | A link is sent unchanged. Bytes are sent as a base64 data URI. `input_images` entries must be an `http(s)` link or a data URI. |
| `n` | `parameters.n` | Z-Image generates one image: `n` other than 1 is refused, and `n` is not sent. |
| `size` | `parameters.size` | `1536x1024` is sent as `1536*1024`. A value that is not width and height in pixels (`auto`, `2K`) is refused. DashScope enforces each model's range. |
| `seed` | `parameters.seed` | |
| `negative_prompt` | `parameters.negative_prompt` | Not sent to Z-Image, which documents no such parameter. |
| `prompt_extend`, `watermark` | `parameters.prompt_extend`, `parameters.watermark` | Booleans. |
| `response_format` | - | DashScope returns links only: any value other than `url` is refused. |
| Any other field, with `x-bf-passthrough-extra-params: true` | `parameters.<field>` | DashScope reads generation switches only inside `parameters`. |

A field that cannot be delivered is refused with HTTP 400 and `extra_fields.error_type` `caller_unsupported_parameter`, with the field in `error.param`, before DashScope is called:

- `resolution`. Alibaba documents no resolution parameter for Qwen-Image: the 2.0, 2.1 and 3.0 series take `size` as width and height from `512*512` to `2048*2048`. Send the `size` you want.
- `quality`, `aspect_ratio`, `output_format`, `background`, `mask` and the other unified image fields DashScope has no parameter for.
- `callback_url`, `client_reference_id`, `expires_after_seconds` and `output_storage_uri`. The synchronous endpoint has no task to control.

A Wan image model (`wan*`) is task-based and is refused on these two routes with HTTP 400 `caller_invalid_request`. A model that is neither `qwen-image-*`, `z-image-*` nor `wan*` is refused with `caller_model_unknown`.

### Response

Each link in `output.choices[].message.content[].image` becomes one `data[]` item with `url`. DashScope keeps a result link for 24 hours; the response does not carry an expiry field yet. `usage.output_images` is DashScope's `usage.image_count`, and `size` is its reported `width` and `height`. Z-Image also reports `input_tokens`, `output_tokens`, `total_tokens` and `output_tokens_details.reasoning_tokens` when `prompt_extend` rewrote the prompt, and the rewritten prompt is returned as `revised_prompt`. A 200 with no image is an error: `provider_empty_result` (HTTP 502), or DashScope's own code when the body carries one.

## Speech (Qwen3-TTS)

`POST /v1/audio/speech` sends one non-streamed request to `{base_url}/api/v1/services/aigc/multimodal-generation/generation`.

| Unified field | DashScope field |
|---------------|-----------------|
| `input` | `input.text` |
| `voice` (one voice name) | `input.voice` |
| `language_code` | `input.language_type`, as given (for example `English`, `Chinese`); omitted when not sent, which leaves DashScope's `Auto` |

`response_format`, `speed`, `instructions`, `with_timestamps` and the other ElevenLabs fields have no Qwen3-TTS field: a request that sets one gets 400 with `extra_fields.error_type` `caller_unsupported_parameter` and the field in `error.param`, before any call to DashScope. A multi-speaker `voice` list is refused the same way.

Qwen3-TTS answers with a link to the audio, not the bytes. Bifrost does not download it: the response is JSON with DashScope's link and its expiry.

```json
{
  "url": "https://dashscope-result-....aliyuncs.com/....wav?Expires=1766113409&...",
  "expires_at": 1766113409,
  "usage": { "input_tokens": 0, "output_tokens": 0, "total_tokens": 0, "billed_characters": 195 },
  "extra_fields": { "provider": "dashscope", "...": "..." }
}
```

`usage.billed_characters` is DashScope's `usage.characters` (reported by Qwen3-TTS-Flash). The same usage is in the `x-bifrost-usage` response header. The OpenAI drop-in route `/openai/v1/audio/speech` answers the same JSON. Streamed speech (`stream_format: "sse"`) is not supported yet.

## Transcription (Qwen3-ASR)

`POST /v1/audio/transcriptions` sends one synchronous request to `{workspace_base_url}/api/v1/services/aigc/multimodal-generation/generation`. The audio is the user message's `{"audio": ...}` item:

- A `url` form field (in place of `file`) is sent unchanged. Bifrost does not download it. A data URL (`data:audio/wav;base64,...`) is sent unchanged too.
- An uploaded `file` is sent as a base64 data URL, with the media type taken from the file name or its header. DashScope limits the encoded audio to 10 MB.
- Sending both `file` and `url` is refused with `caller_unsupported_parameter` naming `url`.

| Unified field | DashScope field |
|---------------|-----------------|
| `language` | `parameters.asr_options.language` |
| `prompt` | a system message whose text is the context |
| `response_format` | only `json`; any other value is refused |

`timestamp_granularities` and the other transcription fields are refused with `caller_unsupported_parameter`. The response carries the text, the `language` DashScope detected, and DashScope's usage: `usage.seconds` (type `duration`) and the token details it reports.

## Open questions

- Which Singapore host serves Qwen3-TTS and Qwen3-ASR is not settled. DashScope's Qwen3-TTS reference names `dashscope-intl.aliyuncs.com`, and its Qwen3-ASR reference names the workspace host `{WorkspaceId}.ap-southeast-1.maas.aliyuncs.com`. Both bases are configurable.

## Authentication

The API key is sent as `Authorization: Bearer <key>`. An `extra_headers` entry named `Authorization` does not replace it.

## Errors

DashScope returns `{"request_id": "...", "code": "...", "message": "..."}` with an error status. Bifrost keeps the status code, puts `code` in `error.code` verbatim and `message` in `error.message`, and sets `extra_fields.error_type`:

| DashScope code | Status | `error_type` |
|----------------|--------|--------------|
| `InvalidParameter` | 400 | `caller_invalid_request` |
| `Arrearage` | 400 | `provider_billing` |
| `AllocationQuota.FreeTierOnly` | 403 | `provider_billing` |
| `InvalidApiKey` | 401 | `provider_auth_failed` |
| `AccessDenied`, `AccessDenied.*`, `Model.AccessDenied` | 403 | `provider_auth_failed` |
| `ModelNotFound` | 404 | `caller_model_unknown` |
| `Throttling`, `Throttling.*` | 429 | `provider_rate_limited` |
| `InternalError`, `InternalError.*` | 500 | `provider_server_error` |
| `ServiceUnavailable` | 503 | `provider_overloaded` |
| `DataInspectionFailed`, `data_inspection_failed`, `IPInfringementSuspect` (content moderation) | 400 | `caller_content_filtered` |

Any other code is classified from its status. A `200` that carries a `code` is turned into an error the same way: `DataInspectionFailed` is 400 `caller_content_filtered`, any other code 502 `provider_server_error`. A `200` with no audio link (speech) or no choice (transcription) is 502 `provider_empty_result`.
