## Overview

Moonshot is integrated as an OpenAI-compatible provider. Bifrost maps Moonshot endpoints for models, text completion, chat completion, Kimi's own Responses API, and Kimi's Anthropic-compatible Messages API.

### Supported Operations

| Operation | Non-Streaming | Streaming | Endpoint |
|-----------|---------------|-----------|----------|
| List Models | ✅ | - | `/v1/models` |
| Text Completions | ✅ | ✅ | `/v1/completions` |
| Chat Completions | ✅ | ✅ | `/v1/chat/completions` |
| Responses API | ✅ | ✅ | `/v1/responses` |
| Anthropic Messages (`/anthropic/v1/messages`) | ✅ | ✅ | `/anthropic/v1/messages` (passthrough) |
| Embeddings | ❌ | ❌ | - |
| Image / Audio / Files / Batch / Video | ❌ | ❌ | - |

## Responses API

Responses requests go to Kimi's own [Responses API](https://platform.kimi.ai/docs/api/responses.md) at `{base_url}/v1/responses`. They are not converted to chat completions, so Responses-only fields reach Kimi. The server-side `web_search` tool is one: when Kimi runs a search, a `web_search_call` item comes back at the front of `output`, and usage is returned as Kimi reports it. A streamed request ends with `response.completed`, which carries the usage.

```bash
curl --location 'http://localhost:8080/openai/v1/responses' \
--header 'Content-Type: application/json' \
--data '{
  "model": "moonshot/kimi-k3.1-pro",
  "input": "What are the top news stories today?",
  "tools": [{"type": "web_search"}],
  "include": ["web_search_call.action.sources"]
}'
```

Kimi's image search is set on the same tool. `search_content_types` with `image` turns it on, `image_settings` sets `max_results` and `caption`, and `web_search_call.results` in `include` returns the images. Bifrost sends `image_settings` to Kimi as the caller wrote it and returns each `results` entry as Kimi sent it.

```json
{
  "model": "moonshot/kimi-k3.1-pro",
  "input": "Find a photo of a red panda.",
  "tools": [{"type": "web_search", "search_content_types": ["text", "image"], "image_settings": {"max_results": 3, "caption": true}}],
  "include": ["web_search_call.action.sources", "web_search_call.results"]
}
```

## Anthropic Messages API

A request to `/anthropic/v1/messages` with a `moonshot/<model>` model is passed through to Kimi's Anthropic-compatible [Messages API](https://platform.kimi.ai/docs/api/messages.md) at `{base_url}/anthropic/v1/messages`. With the default base URL that is `https://api.moonshot.ai/anthropic/v1/messages`.

- The request body is sent byte for byte. The only change is the model id: `moonshot/kimi-k3.1-pro` becomes `kimi-k3.1-pro`.
- The response body, or the SSE stream, is returned as Kimi sent it. Usage is in `message_start` and the last `message_delta`.
- Bifrost authenticates with `Authorization: Bearer <key>`, as Kimi documents, not with `x-api-key`.
- Only the Messages create path is passed through. Other Anthropic paths, such as `/v1/messages/count_tokens`, are not supported for Moonshot.

A custom `base_url` must serve `/anthropic/v1/messages` and `/v1/responses` for these two APIs to work.

## Configuration

<Tabs>
<Tab title="Gateway">

```bash
curl --location 'http://localhost:8080/api/providers' \
--header 'Content-Type: application/json' \
--data '{
  "provider": "moonshot",
  "keys": [
    {
      "name": "moonshot-key-1",
      "value": "env.MOONSHOT_API_KEY",
      "models": [],
      "weight": 1.0
    }
  ]
}'
```

</Tab>
<Tab title="Go SDK">

```go
case schemas.Moonshot:
    return []schemas.Key{{
        Value:  *schemas.NewEnvVar("env.MOONSHOT_API_KEY"),
        Models: []string{},
        Weight: 1.0,
    }}, nil
```
