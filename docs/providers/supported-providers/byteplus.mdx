## Overview

BytePlus ModelArk (Ark) is ByteDance's model platform for international customers. Its chat, Responses and image APIs follow the OpenAI shape with extra fields, and video generation runs as async tasks. Bifrost has its own BytePlus implementation that reuses the shared OpenAI converters where the wire format matches. Key characteristics:

- **OpenAI-compatible chat.** Chat Completions use `/api/v3/chat/completions`.
- **Native Responses API.** Requests go to Ark's own `/api/v3/responses`.
- **Reasoning.** Reasoning models think by default. Bifrost maps `reasoning_effort` onto Ark's `thinking` switch and returns `reasoning_content` as the message's `reasoning`.
- **Tool calling and vision.** Function tools and `image_url` parts use the OpenAI schema. Vision depends on the model.
- **Embeddings.** Served by the multimodal embedding endpoint, one upstream call per input item.
- **Image generation and editing.** Seedream models through `/api/v3/images/generations`.
- **Video generation.** Seedance models as async tasks through `/api/v3/contents/generations/tasks`.

Text-to-speech and speech recognition are a separate BytePlus product with its own key and host, so the BytePlus provider doesn't cover them.

<Note>
This fork also has its own [ModelArk](/providers/supported-providers/modelark) and [Volcengine](/providers/supported-providers/volcengine) providers for the same Ark API. `byteplus` is a separate provider with its own keys and configuration: it is not an alias of `modelark`, and it cannot be the `base_provider_type` of a custom provider.
</Note>

## Setup and configuration

Bifrost calls `https://ark.ap-southeast.bytepluses.com` by default and sends the Ark API key as a bearer token. API keys belong to one region, so to use another region set `network_config.base_url` to that region's host, for example `https://ark.eu-west.bytepluses.com`. The same provider also works against Volcengine Ark in mainland China with `https://ark.cn-beijing.volces.com` and a Volcengine key. Bifrost appends the `/api/v3/...` paths itself, so the base URL is the host only.

Ark only serves models you have activated in the ModelArk console. A request for any other model fails with a 404 whose error code is `ModelNotOpen`. The `model` field takes either a model ID such as `deepseek-v4-flash-260425` or an endpoint ID such as `ep-20260101000000-abcde`.

# 1. Chat Completions

## Request parameters

BytePlus supports the OpenAI chat parameters Ark documents, including `max_completion_tokens`, `temperature`, `top_p`, `tools`, `tool_choice`, `response_format`, `stream` and `stream_options`. For the full parameter reference, see [OpenAI Chat Completions](/providers/supported-providers/openai#1-chat-completions).

Ark hosts ByteDance's Seed models alongside third-party models such as DeepSeek (`deepseek-v4-flash-260425`), GLM and `gpt-oss-120b`. The ModelArk console lists what your account can activate. Some chat models, including `deepseek-v4-flash`, take text only and reject `image_url` parts with a 400.

```bash
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "byteplus/deepseek-v4-flash-260425",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

### Reasoning

Reasoning models such as Seed and DeepSeek V4 think unless told not to. Ark returns the thinking as `reasoning_content`, which Bifrost exposes as the message's `reasoning`. `reasoning_effort` maps onto Ark's values like this:

| Bifrost value | Sent to Ark |
|---------------|-------------|
| `minimal`, `low`, `medium`, `high` | unchanged |
| `xhigh`, `max` | `high`, the top of Ark's range |
| `none` | `thinking: {"type": "disabled"}` and no `reasoning_effort` |
| any effort with `extra_params.thinking.type: "disabled"` | `thinking` only, because Ark rejects `reasoning_effort` when thinking is off |

### Extra parameters

Extra parameters pass through, so Ark-only fields such as `thinking`, `service_tier` or `repetition_penalty` reach the API unchanged.

### Errors

Ark returns OpenAI-shaped errors. Bifrost keeps Ark's string error code, for example `ModelNotOpen`, `InvalidEndpointOrModel.NotFound` or `RateLimitExceeded.EndpointTPMExceeded`, in `error.code`.

# 2. Responses API

Responses requests go to Ark's native `/api/v3/responses`, streamed or not. Ark-only fields such as `thinking`, `caching` and `expire_at` can be sent through extra params.

# 3. Embeddings

BytePlus serves embeddings through the multimodal model `skylark-embedding-vision-251215` on `/api/v3/embeddings/multimodal`. That endpoint fuses every part of a request into one vector, so Bifrost sends each input item as its own call, up to 8 at a time, and returns the vectors in input order with usage added up. An item can mix text, image and video parts, and comes back as one vector. If one call fails, the request fails with that error and no further calls are started; calls already in flight finish, and Ark may bill them.

```bash
curl -X POST http://localhost:8080/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{
    "model": "byteplus/skylark-embedding-vision-251215",
    "input": ["first document", "second document"],
    "dimensions": 1024
  }'
```

| Bifrost parameter | Ark field | Notes |
|-------------------|-----------|-------|
| text part | `input[]` item with `type: text` | |
| image part | `input[]` item with `type: image_url` | URL, or a base64 data URI built from `data` and `mime_type` |
| video part | `input[]` item with `type: video_url` | |
| `dimensions` | `dimensions` | 1024 or 2048 |
| `encoding_format` | - | Only `float` is supported. Other values are rejected with a 400. |

Per-item `dimensions` override the request-level value, since every item is a separate call. `task_type` and `title` are not forwarded to BytePlus. Token-ID inputs aren't supported.

# 5. Image Generation and Editing

Seedream generates and edits images through the same endpoint. An edit request sends its source images as Seedream reference images.

```bash
curl -X POST http://localhost:8080/v1/images/generations \
  -H "Content-Type: application/json" \
  -d '{
    "model": "byteplus/dola-seedream-5-0-pro-260628",
    "prompt": "A lighthouse at dusk, oil painting",
    "size": "2048x2048"
  }'
```

| Bifrost parameter | Ark field | Notes |
|-------------------|-----------|-------|
| `prompt` | `prompt` | Required |
| `size` | `size` | `WIDTHxHEIGHT`, or a tier such as `2K` |
| `n` | (none) | Must be 1. Seedream cannot generate an exact number of images, so any other `n` is a 400 `caller_unsupported_parameter` naming `n`. |
| `input_images` (generation), `image[]` (edit) | `image` | URLs or base64 data URIs. Masks aren't supported. |
| `response_format` | `response_format` | `url` (default) or `b64_json`. Image URLs expire after 24 hours; a response with a URL carries `expires_at` (`created` + 24 hours). |
| `seed`, `output_format` | `seed`, `output_format` | |
| `extra_params.watermark` | `watermark` | |
| `extra_params.sequential_image_generation`, `extra_params.sequential_image_generation_options` | (refused) | Seedream's group generation decides how many images are made, so the price. It is not offered: `sequential_image_generation` other than `disabled`, or non-empty options, is a 400 `caller_unsupported_parameter` naming the field, with no call to Ark. |

Any other extra params, such as `background`, `layer_decomposition` or `optimize_prompt_options`, are sent to Ark unchanged. An image that content safety blocks takes no slot in `data`; it is counted in `content_filter` (`filtered_count` and Ark's codes in `reasons`), and `usage.output_images` counts the images delivered. A response whose every image was blocked is still a 200, with an empty `data` and `content_filter`. Ark refusing the request itself (for example `InputTextSensitiveContentDetected`) keeps Ark's status and code, with `extra_fields.error_type` `caller_content_filtered`.

## Streaming

Set `stream: true` to get each image as soon as Seedream finishes it. Ark streams on Seedream 5.0 lite, 4.5 and 4.0 only. Seedream 5.0 pro and flash reject the request with a 400.

```bash
curl -N -X POST http://localhost:8080/v1/images/generations \
  -H "Content-Type: application/json" \
  -d '{
    "model": "byteplus/seedream-4-5-251128",
    "prompt": "A lighthouse in winter",
    "stream": true
  }'
```

The image arrives whole, as one `image_generation.partial_image` event (`image_edit.partial_image` for edits) carrying its `url` or `b64_json`. The stream ends with one `image_generation.completed` event that carries the usage and repeats the image. If content safety blocks the image before any frame has been sent, the answer is a JSON 400 with Ark's code and `extra_fields.error_type` `caller_content_filtered`. An internal error from Ark is `provider_server_error`, and a stream that completes with nothing delivered or blocked is 502 `provider_empty_result`.

# 6. Video Generation

Seedance video generation is asynchronous. Create a task, poll it, then download the result.

```bash
curl -X POST http://localhost:8080/v1/videos \
  -H "Content-Type: application/json" \
  -d '{
    "model": "byteplus/dreamina-seedance-2-5-260628",
    "prompt": "A paper boat drifting down a rainy street",
    "seconds": "5",
    "size": "1280x720"
  }'
```

| Operation | Endpoint | Notes |
|-----------|----------|-------|
| Create | `POST /v1/videos` | Returns a queued job ID |
| Get status | `GET /v1/videos/{id}` | Poll until `status: completed`. Ark keeps task records for 7 days. |
| List | `GET /v1/videos` | `limit` sets the page size. Ark pages by number, so an `after` cursor is rejected with a 400. |
| Download content | `GET /v1/videos/{id}/content` | Fetches the video from the task's signed URL, which expires after 24 hours. The URL must resolve to a public address. The file is forwarded as it arrives, with no size limit, and is served with a `video/*` content type. |
| Cancel | `POST /v1/videos/{id}/cancel` | Cancels a task that is still queued and returns it with `status: cancelled`. Bifrost queries the task once and sends Ark's `DELETE` only while Ark reports it `queued`. In any other state, or when Ark refuses the cancel because the task has started, the answer is `400` with `error_type: provider_cancel_unsupported` and nothing is deleted. |
| Delete | `DELETE /v1/videos/{id}` | Ark's own `DELETE`: cancels a queued task or deletes a finished one's record. Use the cancel route to cancel safely. |

## Parameter mapping

| Bifrost parameter | Ark field | Notes |
|-------------------|-----------|-------|
| `prompt` | `content[]` text item | Required |
| `input_reference` | `content[]` image item with role `first_frame` | Image to video |
| `video_uri` | `content[]` video item with role `reference_video` | Models that accept reference video only |
| `output_format` | `output_format` | `mp4` (default) or `mov`. Seedance 2.5 only. |
| `seconds` | `duration` | Whole seconds from `2` to `15`, or `-1` to let the model choose the length. A fractional value or one outside that range is refused with a `400`; it is never rounded. Ark refuses a value its model does not take. |
| `size` | `resolution` + `ratio` | Must name a tier and ratio exactly: the short side is `480`, `720` or `1080` and the long side is that tier at `21:9`, `16:9`, `4:3`, `1:1`, `3:4` or `9:16`, so `1280x720` is `720p` at `16:9`. Any other size is refused with a `400`; no nearest tier or ratio is picked. |
| `resolution`, `aspect_ratio` | `resolution`, `ratio` | The direct way to choose them. `aspect_ratio` also accepts `adaptive`. Sent together with a `size`, each overrides the value the size implies; the `size` itself must still be exact. |
| `last_frame` | `content[]` image item with role `last_frame` | |
| `reference_images` | `content[]` image items with role `reference_image` | Can't be combined with first or last frame images |
| `callback_url` | `callback_url` | Sent to Ark unchanged. Ark's callbacks are unsigned. |
| `expires_after_seconds` | `execution_expires_after` | The task's total deadline, `3600` to `259200` seconds. A value outside that range is refused with a `400`. |
| `seed` | `seed` | |
| `audio` | `generate_audio` | Models with audio output only |
| `extra_params.ratio` | `ratio` | Ark's own name for `aspect_ratio`. Accepted as an extra parameter only together with `aspect_ratio` and the same value. |
| `extra_params.reference_videos` | `content[]` video items with role `reference_video` | Added after `video_uri`. Seedance 2.5 takes up to 10, Seedance 2.0 up to 3. |
| `extra_params.reference_audios` | `content[]` audio items with role `reference_audio` | `wav` or `mp3`. Seedance 2.5 and 2.0 only. |
| `extra_params.draft_task_id` | `content[]` draft task item | Turns a draft into the final video. `prompt` is optional when it is set. |

`aspect_ratio`, `resolution`, `last_frame` and `reference_images` are unified request fields: send them as the request's own fields. Naming one only among the extra parameters is refused with `400` `caller_unsupported_parameter`, because a field that affects the price must be visible on the request. Go SDK callers set the field on `Params` and keep the same value in `ExtraParams`, where this provider's converter reads it; the HTTP routes do that for you.

Image references, and the first and last frames, also accept the `asset://<ASSET_ID>` form for media in your Ark asset library.

Other extra params are sent to Ark unchanged. That covers `draft`, `return_last_frame`, `service_tier`, `priority`, `execution_expires_after`, `omni_reference_task_type`, `camera_fixed`, `frames`, `watermark` and `safety_identifier`. Two are refused with a `400`: `model`, which would replace the model the request was authorized and priced for (on every BytePlus operation), and `content`, which would replace the task's content items; name media and drafts through the parameters above instead. A task created with `return_last_frame: true` lists the final frame as a second `videos[]` entry with `content_type: image/jpeg`, after the video, so `GET /v1/videos/{id}/content` still downloads the video. A `mov` output comes back with `content_type: video/quicktime`.

To work from a draft, create a task with `draft: true` at `480p`, then create a second task with `extra_params.draft_task_id` set to the draft's ID as Bifrost returned it. Drafts are valid for 7 days.

A task reports its `size` as `WIDTHxHEIGHT`, built from the resolution tier and ratio Ark returns: `720p` at `16:9` is `1280x720`. It is the nominal size of the tier, not the exact pixel grid Seedance renders, and it is what selects a per-resolution video rate. When Ark reports no ratio or `adaptive`, no `size` is returned and pricing uses the `size` of the original request, if it had one.

## Task object

| Field | Source |
|-------|--------|
| `status`, `provider_status` | Ark's task state, one to one: `queued` → `queued`, `running` → `in_progress`, `succeeded` → `completed`, `failed` → `failed`, `cancelled` → `cancelled`, `expired` → `expired`. `provider_status` is Ark's own word. A state Bifrost does not know reads `in_progress`. |
| `usage.output_tokens` | Ark's `usage.completion_tokens`, the quantity Ark bills a Seedance task by |
| `videos[]` | `type: "url"` entries with Ark's signed links |
| `completed_at`, `expires_at` | Ark's `updated_at` on a succeeded task, and that time plus 24 hours, the lifetime of Ark's links |
| `error`, `content_filter` | A failed task carries Ark's error code and message. When the code is a moderation refusal such as `OutputVideoSensitiveContentDetected`, `content_filter` reports one filtered item with that code as the reason. |

A create that Ark refuses for its input (`InputTextSensitiveContentDetected`, `InputImageSensitiveContentDetected`) comes back with Ark's status and code and `error_type: caller_content_filtered`.

`client_reference_id`, `output_storage_uri` and the upscale fields have no Ark field, so a request that sets one is refused with `400` `caller_unsupported_parameter` before Ark is called. Model availability differs by region, so check the ModelArk console before pointing video traffic at a non-default region.
