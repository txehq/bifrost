## 🍴 Fork changes (txehq/bifrost)

- chore: v2.4.0-sync.5 is a prerelease on top of v2.4.0-sync.4, the fifth batch toward upstream transports/v2.4.0 (TXE-5992). It merges upstream dev 4039d1fdc..dd067e920, the six BytePlus commits, and stops there; v2.3.5 stays the stable release and `latest`
- fork: `byteplus` is added next to the fork's own `modelark` and `volcengine` providers, which are unchanged. All three reach the Ark API; `byteplus` has its own keys and configuration and is not an alias of `modelark`. It is not a `base_provider_type` for custom providers, so it has no custom-provider name or `allowed_requests` to honour
- fork: the CI workflows (`pr-tests`, `release-pipeline`, `run-core-tests`) keep the fork's versions. Upstream's `BYTEPLUS_API_KEY` secrets and `ark.ap-southeast.bytepluses.com` egress for the live provider jobs are not taken, so no CI job calls BytePlus
- fork: BytePlus video downloads fetch the task's signed URL through the SSRF-hardened media fetcher (`providerUtils.FetchMediaURL`): public addresses only, checked at dial time and on every redirect, the provider's proxy honoured, a 256 MiB cap and a 5-minute bound, no credentials sent, and errors that name the URL without its signed query. Upstream fetched it with the provider client, whose dialer admits loopback and private addresses, so a compromised upstream could make Bifrost read an internal address
- fork: a downloaded BytePlus video is always served with a `video/*` type: the file host's type is kept only when it is a well-formed `video/<subtype>`, and anything else (`text/html`, `image/svg+xml`, none) becomes the type the task's output format implies, `video/quicktime` for a `.mov` and `video/mp4` otherwise. `/v1/videos/{id}/content` serves the bytes on the gateway's own origin, so an HTML type would have rendered there. The rule is `providerUtils.VideoContentTypeOr`, which MiniMax's download now shares
- fork: a settled BytePlus video reports its size as nominal `WxH`, built from the task's resolution tier and ratio (`720p` at `16:9` is `1280x720`), instead of Ark's tier label. Video pricing reads the short edge of a `WxH` size, so the label `720p` selected no per-resolution rate and, being non-empty, also replaced the size captured from the request at settlement. With no ratio, or `adaptive`, no size is reported and the captured one is kept
- fork: a streamed Seedream generation ends on its terminal event (`image_generation.completed`, or an error that ends the stream) even when Ark keeps the connection open afterwards. The stream marks itself parked, so cleanup abandons the connection instead of draining it; before, a parked or heartbeating upstream held the stream channel open after the client already had its last event. A `[DONE]` marker is handled the same way, and a body read to EOF is marked exhausted
- fork: a BytePlus embedding request stops starting calls once one fails. Each input is its own Ark call, and before this a rate limit on the first input still sent every remaining input to Ark, again on every retry of the request. Calls already in flight (at most 8) finish
- fork(ui): the log view's split of a video job's outputs into playable videos and image frames is a tested helper (`videoView.utils.ts`)
- test: offline httptest tests for each fork change above, red on the merged upstream code: the download refusal and content type, the `WxH` size, the parked stream (completed, terminal errors, `[DONE]`), a cancelled and a timed-out stream, and the embedding fan-out. Provider-harness folder 288 pins the BytePlus video lifecycle (create, poll to completion with a `WxH` size, download as `video/*`, delete); Seedance bills per clip, so every row is `[PREVIEW]` and runs only with `INCLUDE_PREVIEW=1`
- test: benchmarks. The shared paths upstream's change touches keep their allocations: OpenAI and Groq chat conversion 67 allocs/op, chat with a reasoning effort 75 (OpenAI), 72 (Groq) and 78 (Nebius), an OpenAI Responses request marshal 48 and 49 with reasoning, video cost input 9 and settlement dimensions 1. BytePlus pays for its own compatibility: a Responses marshal with reasoning 53 allocs/op (the `reasoning.summary` removal), chat with `reasoning_effort: none` 12 against 8 for `low`. New paths: BytePlus chat round trip 106 allocs/op, a streamed Seedream generation 189 (it ends on a connection that is closed, not reused), an embedding call 73 for one input and 481 for eight
- note: pricing. BytePlus bills Seedance on the task's completion tokens. This release prices a BytePlus video per second from a catalog or custom rate, by resolution band when the size is known; upstream's token rate for video (0c8fc4960) is not part of this batch
- note: module versions. This fork publishes no core, framework or plugin module versions: their module paths stay `github.com/capsohq/bifrost/...`, their version files and the transport's requires are unchanged, and the workspace builds them from source. Upstream's core and framework changelog entries are folded in above
