## 🍴 Fork changes (txehq/bifrost)

- chore: v2.4.0-sync.8 is a prerelease on top of v2.4.0-sync.7 (TXE-6519) with no upstream commits taken. It is the release that carries the whole Bifrost–Tokun contract base (TXE-6523), plus the fork tickets merged since v2.4.0-sync.7. v2.3.5 stays the stable release and `latest`
- fork: **contract base (TXE-6523), complete in this release.** New in this release: TXE-6517 (BF4, BF8, BF9), TXE-6521 (BF11, BF12, BF13, BF14), TXE-6524 (ElevenLabs: BF4, BF7) and TXE-6526 (Gemini API images: BF4, BF7, BF10). Carried from earlier prereleases: TXE-6518 (BF3, BF5, BF6, BF10; v2.4.0-sync.6), TXE-6519 (BF1, BF24; v2.4.0-sync.7) and TXE-6522 (BF21, BF22; in the v2.4.0-sync.7 build, listed below)
- fork: **TXE-6517** (BF4, BF8, BF9; contract C4, C6) every error a client receives carries `extra_fields.error_type` from the closed vocabulary: the declared type, or what `ClassifyErrorType` infers. `x-bifrost-error-type` is written on every error, so routes that answer in a vendor-native envelope give the type too. Governance refusals are `policy_*`, never `provider_auth_failed`. Four new types: `caller_content_filtered`, `caller_unsupported_parameter`, `provider_empty_result`, `provider_cancel_unsupported`. `schemas.NewUnsupportedParameterError` and the unified-field declaration (`UnifiedFieldDeclarer`, `CheckUnifiedFields`) return 400 `caller_unsupported_parameter` with `error.param` for a unified field a provider cannot deliver. A speech 200 with no audio is 502 `provider_empty_result`
- fork: **TXE-6521** (BF11, BF12, BF13, BF14; contract C7) the shared, vendor-independent part of async video tasks: the task object gains `provider_status` and the `cancelled` and `expired` statuses, video create gains the four task control fields (`callback_url`, `client_reference_id`, `expires_after_seconds`, `output_storage_uri`), `expires_at` is on the task object, and `POST /v1/videos/{id}/cancel` exists. No provider is changed: each vendor's status table, control-field conversion and cancel call come with its own ticket
- fork: **TXE-6524** (BF4, BF7; contract C4, C5, C6, C10; ElevenLabs vendor sheet sections TTS, STT and sound effects) on the `elevenlabs` provider: speech sends only the `voice_settings` the caller gave; the credits of the `character-cost` header are `usage.vendor_cost {amount, unit: "credit"}`, in `x-bifrost-usage` for a byte response and on the SSE `speech.audio.done` frame, with the header still forwarded; transcription `usage` is `{type: "duration", seconds}` from `audio_duration_secs`; unmapped transcription form fields (`keyterms`, `transcript_edit`, `detect_speaker_roles`) reach the vendor; a transcription 200 with no transcript is 502 `provider_empty_result`; a 422 validation error keeps the vendor's raw body; sound effects refuse an out-of-range `duration_seconds` or `prompt_influence` with 400 `caller_unsupported_parameter` instead of clamping, and no longer report the requested duration as `usage.audio_seconds`
- fork: **TXE-6526** (BF4, BF7, BF10; contract C4, C5, C6; Gemini vendor sheet sections image generation and image edit on the Gemini API) on the `gemini` provider's image models: a field that cannot be delivered (`n` above 1, a `size` with no supported ratio, `quality`, `mask`) returns 400 instead of being dropped; `resolution` maps to `imageSize`; thinking tokens and image counts are in `usage`; a vendor block is 200 with `content_filter`; URL input images are sent
- fork: **TXE-6427** (BF2, BF17, BF18, BF19; contract C8) batches on `openai`, `azure`, `gemini` and `vertex`: `POST /v1/batches` takes inline `requests` in OpenAI shape (Gemini and Vertex lines go through the sync operation's converter); `GET /v1/batches/{id}/results` returns one line per input line with `status`, the OpenAI-shaped body and the sync operation's unified `usage`, merges the error file for OpenAI and Azure, and pages with `limit`, `has_more` and `next_cursor`; retrieve, cancel and results use only the key named in `x-bf-api-key` or `x-bf-api-key-id`; `metadata` and `output_expires_after` take effect on the unified route
- fork: **TXE-6530** (BF7; contract C5, C4) a non-streaming `/v1/audio/speech` response keeps the audio as its body, names the format actually returned in `Content-Type`, and carries the unified speech usage as JSON in the new `x-bifrost-usage` response header. A character count the vendor reports is no longer overwritten by Bifrost's own count (MiniMax's goes to `usage.billed_characters`). OpenAI-shaped speech requests no longer carry the ElevenLabs-only fields. A transcription form field the caller repeats reaches the vendor with every value
- fork: **TXE-6528** (BF4; contract C3, C4, C5, C6; OpenAI vendor sheet, image generation and edit) an OpenAI image request reaches OpenAI with every field the caller sent or returns 400 naming the field; an edit whose input images are links reaches OpenAI with the links
- fork: **TXE-6536** (BF4, BF7, BF10; contract C4, C5, C6) Imagen on Vertex and Gemini reports how many images were delivered and how many were blocked and why, and refuses `quality` and `background` with 400 instead of dropping them
- fork: **TXE-6544** (BF4, BF7; contract C4, C5) `/v1/audio/transcriptions` accepts `url` without `file`: Groq receives the URL unchanged and Bifrost never downloads it; any other provider returns 400 `caller_unsupported_parameter` with `error.param` `url`. When an OpenAI-compatible transcription response carries `duration` and no `usage`, Bifrost reports `usage{type: "duration", seconds}`
- fork: **TXE-6546** (BF4, BF7; contract C4, C5) Cohere embeddings fill usage from `meta.billed_units` (image count in `usage.input_images`), convert the unified `task_type` to `input_type`, and no longer default `input_type` to `search_document`: a request with neither returns 400 `caller_unsupported_parameter` on `task_type` before any upstream call
- fork: **TXE-6596** (BF7; contract C5) Cohere chat usage reports `billed_units` as `prompt_tokens` and `completion_tokens`; the processed counts move to the new `usage.processed_tokens{prompt_tokens, completion_tokens}`
- fork: **TXE-6666** (contract C2, C4, C5, C6, C12; no BF item) new `tencent` provider for Tencent Cloud TokenHub's Hy image models (`hy-image-v3`, `hy-image-v3.5-*`), image generation only
- fork: **TXE-6959** (contract C5; follow-up to TXE-6531; no BF item) Bifrost's computed cost, span attributes and the Prometheus and OTel counters carry OpenAI's 30-minute and 12-hour cache-write tiers. The tier list lives in one place, and a test fails when a tier field is added without being listed
- fork: **TXE-6638** (contract C3, C4, C12, C14; no BF item) embeddings through OpenAI-compatible custom providers configured the way Tokun's reconciler writes them (DeepInfra, Vercel AI Gateway) are proven to return `usage.prompt_tokens`; no gateway code change. The provider harness now skips a provider whose key variables are all unset, with a passing "skipped: no key" assertion
- ci: **TXE-6978**, **TXE-6981**, **TXE-7029** (no BF item) the egress allowlist check stops reading documentation links as dialled hosts, knows each harness provider's default host, and never requires a host under a reserved TLD
- fork: **first released in v2.4.0-sync.7 and not listed in its notes** (they merged before that tag):
  - **TXE-6522** (BF21, BF22; contract C10) a stream's final frame carries the same usage as the non-streamed response; harness cases pin a vendor error before the first frame and frame-by-frame forwarding
  - **TXE-6438** (BF6, BF7; contract C5) every sync image response carries `usage.output_images`, the number of images the vendor delivered
  - **TXE-6531** (BF7; contract C4, C5) OpenAI's 30-minute and 12-hour cache-write tiers are in unified usage
  - **TXE-6534** (BF7; contract C5) Anthropic usage reports web fetch and code execution request counts under `usage.tool_usage`
  - **TXE-6589** (BF8; contract C6) Cohere errors carry `error_type` and keep Cohere's status
  - **TXE-6635** (contract C4 agreement two; no BF item) `/v1/embeddings` forwards top-level extra fields to the vendor with or without `x-bf-passthrough-extra-params`
  - **TXE-6547** (no BF item) Moonshot Responses call Kimi's `/v1/responses`, and `/anthropic/v1/messages` with a `moonshot/<id>` model passes through to Kimi's Anthropic-compatible endpoint
  - **TXE-6958** (no BF item) Responses `web_search` keeps `image_settings`, and a `web_search_call` keeps its `results`
  - **TXE-6965** (no BF item) every native Messages passthrough carries the Anthropic raw-body adapters, so a redaction guardrail can rewrite the body for every provider
- breaking: callers that relied on a silent rewrite now get a 400 or a different value. ElevenLabs sound effects with an out-of-range `duration_seconds` or `prompt_influence` (was clamped); ElevenLabs speech no longer sends zero voice settings the caller did not write; Cohere embeddings with neither `task_type` nor `input_type` (was `search_document`); OpenAI, Gemini API and Imagen image requests with a field the vendor cannot take (was dropped); Cohere chat `prompt_tokens` and `completion_tokens` are billed units (were processed counts)
- test: each ticket ships unit tests in the packages it changes and provider-harness cases validated offline; the harness folders added since v2.4.0-sync.7 include 301 (batch contract), 304 (TTS usage header), 315 (Cohere embeddings), 321 (custom-provider embeddings), 330 (error types) and 402 (ElevenLabs contract). No live provider run is part of this release (`--skip-core-test`)
- note: module versions. This fork publishes no core, framework or plugin module versions: their module paths stay `github.com/capsohq/bifrost/...`, their version files and the transport's requires are unchanged, and the workspace builds them from source
- preserved: everything v2.4.0-sync.7, v2.4.0-sync.6, v2.4.0-sync.5 and earlier releases listed under Fork changes
- chore: the Helm chart is 2.1.52-sync.8, a prerelease; `appVersion` is 2.4.0-sync.8, so an empty `image.tag` selects `v2.4.0-sync.8`
- note: the CLI and Migration CLI are unchanged: v1.0.1 and v0.1.1 remain their stable releases
- note: the image and the OCI chart are private packages, so pulling them needs a token with `read:packages`
