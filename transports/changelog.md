## 🍴 Fork changes (txehq/bifrost)

- chore: v2.4.0-sync.15 is a prerelease on top of v2.4.0-sync.14 with no upstream commits taken. It carries the 31 fork PRs merged since v2.4.0-sync.14 (`git log --first-parent transports/v2.4.0-sync.14..<release commit>`, #394 through #425). v2.3.5 stays the stable release and `latest`. The Helm chart is 2.1.52-sync.15.

### Dollar budgets (visible changes; read before rolling a gateway whose virtual keys carry a dollar budget)
- fork: **TXE-7957** (#410) a request from a key with a dollar budget (on the key, its team or customer, a provider config or a model config) on a model the price book cannot price is refused 403 `policy_model_blocked` / `model_unpriced` before the call, where it was served before. Also refused under such a budget: a file or blob batch whose models cannot be priced up front, a passthrough body mixing models or with a task naming none, and cached-content creation. The fix for an operator is a pricing override for the model.
- fork: **TXE-8016** (#423) (1) a model counts as priced for admission only under a provider key that may serve the request (the pinned key, else the keys the virtual key allows; enabled keys only; for a batch only keys with `use_for_batch_api`): a model priced only through a key the caller cannot use is now refused 403 `model_unpriced` (`policy_model_blocked`) up front. (2) Whether a $0 answer is unpriced is read from the cost calculation (`modelcatalog.AnswerPriceStatus`), not inferred from the total: a flex answer at zero flex rates, or one whose row (or free fallback, or override) prices nothing above zero, is free and no longer refuses the model for its caller. (3) A token-count passthrough naming its model only in the body refuses nothing.
- fork: **TXE-7977** (#419) until one answer on a price book row has priced above $0 for a (budget, virtual key) on a replica, that caller (virtual key, else user, else presented credential; requests presenting nothing share one) runs one request at a time on the row; a concurrent request is refused 429 `model_pricing_unconfirmed` (error type `policy_rate_limited`, `x-bifrost-retry-after-ms: 1000`). After an answer prices above $0 the row is confirmed and the limit lifts. Callers without a dollar budget and Live/Realtime units are unaffected. TXE-7957's after-the-fact refusal is keyed by the same caller. The state is per replica: a restart re-probes.
- fork: **TXE-7963** (#418) refused 403 `policy_model_blocked` before the call: (1) type `background_unsettled` for a Responses or Interactions create asking for background delivery, through the typed field, extra params, a raw body or a passthrough body, in any key case; (2) type `job_unsettled` for video create, edit or remix and batch create while provider job accounting is off (`client.disable_provider_job_accounting`) or the logging plugin is absent.
- fork: **TXE-8013** (#421) a request whose result is delivered elsewhere is refused 403 `background_unsettled` (`policy_model_blocked`) before the call: (1) a Runware task with a `deliveryMethod` other than `sync`, or with a `webhookURL` (a `videoInference` task counts unless it asks for `sync`); (2) any request charged on its answer that names `webhook`, `webhook_url`, `webhookURL`, `callback_url`, `callbackURL` or `webhook_config` in a passthrough body (JSON, multipart or urlencoded form fields), extra params (including the `extra_params` wrapper) or a raw body. Video and batch jobs are not refused for a callback; they are charged at settlement. Backstop: a budgeted passthrough answered with only a queued acknowledgment logs a warning, and its model is refused under the budget from then on. This reverses #410's queued-acknowledgment exemption under a budget.
- note: callers without a dollar budget are unaffected by the five entries above.

### Forwarded bodies
- fork: **TXE-8012** (#415) (1) a forwarded body is read by its declared Content-Type, never its first byte: one classifier (`schemas.ClassifyForwardedBody`) is shared by core's guard, the passthrough router, governance's model and object gates, and the provider readers. JSON sent to a passthrough route under a non-JSON type gets no body-model governance. (2) New 400 `caller_invalid_request`: outside the upload routes (`schemas.FileUploadRoutes`: `POST /v1/files`, `/files`, `/openai/files`, `/openai/v1/files`, `/v1/uploads/{id}/parts`, `/upload/{v}/files`), a body declared as a non-JSON type (or undeclared and not opening like JSON) that opens like JSON under any encoding must be strict JSON with no repeated member, and must name neither `model` nor `stream` at its root (in any casing) nor a provider object; declared JSON Lines naming one is refused too. Since `stream` is gated, a forwarded JSON body giving it in two casings (`stream` and `Stream`) is refused like `model`. Media types (audio, image, video) are read as JSON text only when they are valid UTF-8, so audio bytes pass and JSON declared as audio does not; headerless raw audio (`audio/l16`, `audio/pcm`, mu-law, A-law) whose first byte is `{` or `[` is checked like any body, as before, so about 1 in 128 such streams that are not strict JSON are refused. (3) Upload routes forward content as files (batch `.jsonl` in any SDK shape); a multipart part with a filename is a file, and a `text/plain` upload opening with `{` is forwarded. (4) Installing a `LargePayloadHook` panics at startup; none is installed in this fork.
- fork: **TXE-7994** (#411) a forwarded body that repeats a member, or that is declared JSON but does not parse strictly, is refused 400 where it was forwarded before.

### Request conversion (the converter delivers a field, converts it as documented, or refuses it)
- fork: **TXE-7063** (#409) on `/v1/chat/completions` (unary and streaming) for every provider that sends the OpenAI chat shape (the shared OpenAI handler, Vertex's OpenAI-shape models, xAI batch lines), `prompt_cache_retention` or `prompt_cache_options` to a compatible vendor returns 400 unless the model's record lists the field, and a non-`default` `service_tier` on Gemini's OpenAI-shape route returns 400. `prompt_cache_key` alone behaves as before.
- fork: **TXE-7954** (#414) a reasoning setting the vendor would serve at a level the caller did not ask for returns 400 naming the field: `none` on a model that always reasons, a Mistral effort other than `none` or `high`, `none` on Vertex Model Garden models, an effort on an xAI model that rejects it, `none` on MiniMax M3.1, `none` on BytePlus with thinking not disabled, and `reasoning.max_tokens` on DeepSeek, GLM and Qwen. A DeepSeek effort with thinking enabled is now sent instead of being reduced to "thinking enabled".
- fork: **TXE-8011** (#422) no other provider changes a reasoning setting outside the documented conversions: Perplexity `reasoning.max_tokens` without an effort, and a DeepSeek reasoning level that cannot be served with thinking on, return 400 naming the field.
- fork: **TXE-7116** (#395) a streamed OpenAI or Azure image request with `n` greater than 1 returns 400; send `n: 1` with `stream`, or drop `stream` to get `n` images in `data[]`.
- fork: **TXE-7027** (#396) a custom provider on the `openai` base whose `allowed_requests` has `chat_completion` but not `responses` serves `POST /v1/responses` as one chat completion upstream, checked as chat, where sync.14 refused it with 400 `unsupported_operation`.

### Providers, batch and video
- fork: **TXE-7033** (#394) a `/v1/embeddings` batch line with several inputs is refused 400 on Gemini and Vertex, naming the line, before any upstream call; send one input per line.
- fork: **TXE-7030** (#407) `/genai/v1beta/models/{model}:asyncBatchEmbedContent` creates one Gemini embedding batch job (it was answered 400 as a Responses request), and a `/genai` batch get returns the job's results at `metadata.output`.
- fork: **TXE-7953** (#424) the `/genai` batch routes (create, get, list) return Gemini's own job object unchanged: `BATCH_STATE_PENDING`, `metadata.model`, `metadata.displayName` and `metadata.@type` are no longer lost.
- fork: **TXE-8031** (#420) a retrieve (every `*_retrieve` request type) is read under a quarter of `client.max_response_body_size_mb` (128 MiB by default); a larger retrieve answer is refused with `bifrost_internal`. Converting a Gemini inline batch job for `/genai` now allocates 3.3 bytes per job byte instead of 19.4. Raise `client.max_response_body_size_mb` to raise the limit.
- fork: **TXE-8032** (#425) a list answer is read under the same retrieve limit, and Gemini's batch list stops decoding inline results; a larger list answer is refused with `bifrost_internal`. Downloads keep the whole limit.
- fork: **TXE-7040** (#402) `GET /v1/videos/{id}/content` and `GET /openai/v1/videos/{id}/content` take `?index=N` (default 0, in `videos[]` order) to fetch any video of a multi-video task; a non-zero index past the task's videos, or a malformed one, returns 400 where it silently returned the first video.
- fork: **TXE-7304** (#399) BytePlus Seedream `n` from 2 to 15 asks for a group of up to `n` images (it was refused), and billing counts the images delivered.
- fork: **TXE-6543** (#405) the `azure` provider sends a model of the `mai-image` family to `<endpoint>/mai/v1/images/generations` (Microsoft MAI-Image on Azure AI Foundry).
- fork: **TXE-7328** (#397) with object storage for logs, a failed merge upload of a late completion's output is retried instead of losing the output; the pending-entry eviction TTL is `pending_log_ttl` (default 15m).

### Billing and pricing
- fork: **TXE-7406** (#401) requests on custom providers and on providers whose name differs from the datasheet's are priced at the base provider's or datasheet-name provider's rate, where they were logged with no cost; Bifrost dashboards and Bifrost-enforced budgets now count them.
- fork: **TXE-7073** (#400) Azure Speech reports `estimated_billed_characters` by Azure's billing rule (SSML markup except the `<speak>` and `<voice>` tags, Han characters counted twice), and Bifrost's Azure TTS cost rises to it. **TXE-8029** (#417) a test pins the billed markup per parameter, naming Tokun's `azure_tts_characters` rule.
- fork: **TXE-7069** (#403) and **TXE-7996** (#412) a Kimi prompt-cache write is priced at the TTL the provider receives, on every request path (typed field, extra params, raw body, custom providers).
- fork: **TXE-7101** (#404) the video tier-reader table is checked against every converter: xAI, BFL, VolcEngine and ModelArk jobs sent with `resolution` and no `size` are charged their band, and MiniMax reads the typed field.

### Breaking changes
- breaking: **TXE-7957** (#410), **TXE-8016** (#423), **TXE-7977** (#419), **TXE-7963** (#418), **TXE-8013** (#421): new 403 and 429 refusals for keys with a dollar budget, as listed under Dollar budgets. Give every model such a key uses a price, or an override.
- breaking: **TXE-8012** (#415) and **TXE-7994** (#411): a forwarded body declared as a non-JSON type that opens like JSON, or any forwarded body that repeats a member or is declared JSON but not strict, is refused 400 `caller_invalid_request`. Send JSON as UTF-8 `application/json`, strict, giving each member once.
- breaking: **TXE-7063** (#409), **TXE-7954** (#414), **TXE-8011** (#422): a field a vendor would drop or change (prompt-cache fields, `service_tier` on Gemini's OpenAI-shape route, the listed reasoning settings) returns 400 naming the field where it was silently dropped or changed.
- breaking: **TXE-7116** (#395) a streamed OpenAI or Azure image request with `n` > 1 returns 400.
- breaking: **TXE-7033** (#394) a multi-input embeddings batch line on Gemini and Vertex returns 400.
- breaking: **TXE-8031** (#420) and **TXE-8032** (#425) a retrieve or list answer larger than a quarter of `client.max_response_body_size_mb` returns `bifrost_internal`.
- migrations: none. `framework/configstore/migrations.go` and `framework/logstore/migrations.go` are unchanged since v2.4.0-sync.14, and no table struct in `framework/configstore` or `framework/logstore` changed. v2.4.0-sync.14 runs on this release's schema and a rollback needs no schema step.
