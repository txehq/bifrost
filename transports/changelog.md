## 🍴 Fork changes (txehq/bifrost)

- chore: v2.4.0-sync.16 is a prerelease on top of v2.4.0-sync.15, the sixth batch toward upstream transports/v2.4.0 (TXE-6085, under TXE-5855). It merges upstream dev dd067e920..8207f16e3, the ten commits above, and stops there; v2.3.5 stays the stable release and `latest`.

### GitHub Copilot: adopting token auth (visible changes; read before rolling a gateway with Copilot keys)
- fork: **TXE-6085** the fork takes upstream's token-only Copilot auth (decision 2026-11-22). A key that held only GitHub App credentials has no token after the upgrade: key selection never picks it, and the gateway logs one error per such key at startup naming the provider and the key and the fix (Sign in with GitHub, or a fine-grained PAT). The report uses core's own credential rule (`bifrost.KeyHasCredential`), which key selection now calls at its four sites, so the two cannot disagree; any provider's key without a credential, including an `env.` reference that resolved to nothing, is reported the same way. No message carries a credential.
- fork: **TXE-6085** stored GitHub App credentials are kept for a rollback. The `github_copilot_*` columns stay, with their data; the fork keeps migration `add_github_copilot_config_columns` (upstream removed it), whose rollback still refuses to drop them. Nothing reads them at runtime. A save that marks a plaintext key row encrypted (the startup encryption pass, or any key save while encryption is on) now encrypts that row's App columns too, with the same encoding the older binary wrote, so a binary with App auth still loads the key.
- fork: **TXE-6085** a `config.json` written for App auth still loads: the `github_copilot_key_config` block is ignored and the key is reported. `config.schema.json` and the chart's `values.schema.json` no longer describe the block.
- fork: **TXE-6085** Copilot sign-in reaches GitHub through the github-copilot provider's own proxy (else the inherited global proxy, else the global proxy enabled for API traffic) and its `network_config` TLS settings (`ca_cert_pem`, `insecure_skip_verify`), the egress its inference takes; upstream used the global API transport only. Both sign-in replies carry a credential and are sent `Cache-Control: no-store`. The routes are authenticated management routes. The key form stops polling at the device code's lifetime (900 s when GitHub gives none, at most 1800 s).

### Breaking changes
- breaking: **TXE-6085** GitHub App auth and GitHub Enterprise (`*.ghe.com`) domains for GitHub Copilot are removed, and with them organization billing through an App installation. Give each Copilot key a token: sign in with GitHub on the key, or paste a fine-grained personal access token with the Copilot Requests permission; usage bills to that user's Copilot seat. A Helm values file that still sets `github_copilot_key_config` fails chart validation.
- migrations: configstore unchanged in effect (`add_github_copilot_config_columns` keeps its ID and columns; its model moved to `tables.TableKeyGithubCopilotApp`). ClickHouse log store: a new step creates `user_agent_mappings` (`CREATE TABLE IF NOT EXISTS`, then additive column reconciliation). SQL log stores unchanged. v2.4.0-sync.15 runs on this release's configstore schema; it ignores the new ClickHouse table.
