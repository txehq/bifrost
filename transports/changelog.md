## ✨ Features

- **Agent Gateway (A2A)** - Bifrost registers, governs, logs and traces A2A agents: agent registrations and push state are persisted, the runtime serves agent cards and tasks over HTTP and a shared gRPC listener, access is governed per virtual key, activity lands in a new agent logs workspace, and the catalog, push management and settings are managed from the dashboard and config.json `agents`. Private push callbacks are opt-in (`a2a_allow_private_push_callbacks`) (#7772-#7783, #8125, #8204, #8206)
- **GPT Live** - Voice sessions on OpenAI's Live API: core structs, session handling, WebRTC, attach and SIP routes, the content route, cost tracking (`input_cost_per_second`), key selection and logging, with Live in the custom OpenAI provider UI (#7721-#7728, #7993, #7999, #8011, #8133, #8202, #8203)
- **Provider-Injected Tools** - A provider's `injected_tools` config attaches MCP tools (web search first) that pass tool filters, are rewritten into the request and executed server side on chat, Responses and the Anthropic passthrough path, streaming included, with a web search tab in provider configuration (#8021-#8030)
- **Normalized Decisions** - `/v1/decisions` takes the OpenAI-shaped decision request (questions in order, `predicate`/`choice`/`score` types, choices and levels), with OpenAI native decisions for `gpt-6-luna`, an `/openai/v1/decisions` route, Laya-specific answer fields, Cloudflare Workers AI envelope unwrapping for Clef, decision-model classifiers in the complexity router and decision-specific pricing rates (#7982, #8007, #8059, #8080, #8181, #8191-#8193, #8249)
- **Responses Tool Vocabulary** - The `shell` and `apply_patch` tools and their call and output message types stream and replay across providers, `allowed_callers` is translated between Anthropic and OpenAI, Gemini code execution works on the Responses API, computer tools are muxed between the OpenAI and Anthropic styles with batched `actions`, and Bedrock drops the hosted tools it rejects (#7292, #7293, #7301, #7668, #7711, #7733, #7979, #7980, #8093)
- **Pricing Controls** - `ignore_provider_cost` prices a provider from the catalog instead of its reported cost (stored breakdown and tracing included), 100k-token pricing tiers, lowercase model-name pricing fallback, and the opaque provider total stays out of the input split (#8052-#8057, #8144, #8165, #8229)
- **Compat Routing** - `force_reasoning_only_models_to_responses` routes chat+tools requests to the Responses API for models without `reasoning_with_tool_calls` support (#7806, #7807)
- **Logs and Logstore** - `object_storage_exclude_request_types` keeps chosen request types in the database, ClickHouse `max_query_size` is configurable (16 MiB default), raw request and provider error bodies are exported for failed requests, plugin logs join the exported S3 snapshot, overhead breakdown storage is restructured, the logs details sheet keeps its header and state, background jobs get their own notification tab (#8036, #8047, #8050, #8061, #8126, #8211, #8227, #8240)
- **Management API** - `x-bifrost-request-id` on every response (provider `x-bifrost-*` headers are no longer forwarded), `ReloadProvider` tells added providers from edited ones, BackgroundJobs RBAC permissions, an optional `disabled` field on virtual key MCP configs, generic SSO login `displayName`, and attribution context keys deprecated in favour of `ctx.Grant()` (#7975, #8045, #8101, #8105, #8130, #8132)
- **Helm** - Chart synced with `config.schema.json`, `topologySpreadConstraints` and `extraContainers` with native-sidecar guards (#8187-#8189)
- **xAI Realtime** - Realtime client secrets and native credentials for xAI (core/providers/xai/realtime.go)
