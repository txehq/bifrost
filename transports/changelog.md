## 🍴 Fork changes (txehq/bifrost)

- chore: v2.4.0-sync.7 is a prerelease on top of v2.4.0-sync.6 (TXE-6518) with no upstream commits taken: it carries the Bifrost–Tokun contract's two deployment switches (TXE-6519, work items BF1 and BF24). v2.3.5 stays the stable release and `latest`
- fork: **BF1** `client.disable_provider_job_accounting`, default `false`, so a deployment that does not set it is unchanged. When true the logging plugin writes no provider job row when a video task or a batch is created or polled, settles nothing inline from `/v1/batches/{id}/results` or a terminal video retrieve, and starts neither the batch accounting sweeper (one-minute tick) nor the video accounting sweeper (30-second tick); a sweeper already running when the switch is saved is cancelled. Bifrost then makes no call to a vendor outside a caller's request (contract C3). Retrieving, cancelling and deleting a batch, and retrieving, deleting and downloading a video, work without the row. Read through `GET /api/config`, saved through `PUT /api/config`, and applied on save: the server re-wires the sweepers when the value changes
- fork: **BF24** `client.disable_passthrough_sse_heartbeat`, default `false`. When true a streamed `text/event-stream` passthrough response carries only the vendor's bytes: the SSE comment heartbeat the gateway writes during an idle gap is off for every provider, so a caller that promises its clients the vendor's protocol reads an unchanged stream (contract C11). The router reads the switch at the start of each passthrough stream, so a save applies to the next stream
- fork: both switches are columns on `config_client` (migration `add_client_config_fork_deployment_switch_columns`, backfilled `false`), enter the client config hash only when set, are documented in `transports/config.schema.json` and the management OpenAPI, and are typed for the dashboard
- test: unit tests in `plugins/logging` (neither sweeper starts and no job row or inline settlement is written while the switch is set; both resume when it is cleared), `transports/bifrost-http/server` (the wiring applies the switch with or without a client, and a client-config reload, including a save through `PUT /api/config`, re-wires when the plugin's state disagrees with the config), `transports/bifrost-http/integrations` (an idle SSE passthrough stream is byte-identical to the vendor's with the switch set, and carries the heartbeat by default), `transports/bifrost-http/handlers` (both switches are copied only when sent and read back through `GET /api/config`) and `framework/configstore` (migration and hash). Provider-harness folder 329 runs against the provider error fixture with both switches set: a video create and a batch create are followed by no vendor call for 70 seconds, longer than both ticks; the video's retrieve, download and delete still work; and an idle SSE passthrough stream reaches the caller byte for byte
