## 🔒 Security

- **Proxied requests are pinned to the address the policy checked** - guarded HTTP clients (catalog and datasheet fetches, OpenAPI spec previews, RSS feeds) and MCP clients that reach their destination through a proxy now open a tunnel to the address the destination policy resolved and approved (CONNECT ip:port, or SOCKS5 to the IP, plain http included) instead of handing the proxy the hostname to resolve again. A DNS answer that changes after the check (rebinding) can no longer carry the request to a private, loopback or metadata address. The proxy's credentials, TLS settings and private-network reachability are unchanged
- **Unresolvable proxied destinations are refused** - a hostname the gateway cannot resolve is refused on every proxied guarded path instead of being left to the proxy, as MCP clients already were: nothing could check where the proxy would send it. A deployment whose DNS lives only behind the proxy must let the gateway resolve the catalog, datasheet, OpenAPI and MCP hosts it reaches through that proxy
- **Proxied MCP OAuth requests are pinned to the checked address** - MCP OAuth discovery, dynamic client registration and token requests (every hop, redirects included, of a chain whose later URLs come from the remote MCP server) that go through a proxy now open a tunnel to the address the destination policy approved, under both the public-only and the allowlisted policy, instead of handing the proxy the hostname to resolve again. A direct OAuth request whose destination happens to be a proxy's address is no longer dialed outside the destination policy
- **The catalog URL check is pinned behind a proxy** - the reachability check for a pricing, model-parameters or MCP-library URL saved over the API applies the public-only policy to the destination before the proxy is contacted and tunnels to the checked address, so a name resolving to loopback or turning private after the save-time check is refused, and the check no longer keeps an idle connection open after it returns
- **Agent credential references are stored without their resolved values** - an agent registration's discovery or runtime header, OAuth client credential or TLS material that references an environment variable or vault secret is written to the database as the reference only, whatever the encryption setting; the resolved value used to be stored next to it in plaintext, because encryption covers literals only. Loading resolves the reference again. A row saved by an earlier version keeps its stored value until the registration is next saved
- **Provider extra headers need real auth to reference server secrets** - while dashboard auth is disabled or unconfigured, creating or updating a provider refuses an extra header that introduces or repoints an `env.` or `vault.` reference (403), since its resolved value is sent to the provider on every request. Unchanged references, removed headers and literal values are still accepted
- **Provider keys need real auth to reference server secrets** - while dashboard auth is disabled or unconfigured (or a key route is whitelisted), creating or updating a provider key refuses an `env.` or `vault.` reference in any of its fields (the value, and every Azure, Vertex, Bedrock, Bedrock Mantle, vLLM, Ollama, SGL, Databricks, Copilot, Cloudflare, OAuth and per-alias credential) that is new or moved to another field (403), since the gateway resolves it and sends the server secret to the provider. References kept where they are, masked values echoed back from the dashboard, removals and literal values are still accepted
- **Virtual keys cannot manage fine-tuning through passthrough** - no provider records which key created a tuning job or tuned model, so under the shared provider key a virtual key could list every job and cancel another tenant's. With `client.enforce_vk_object_ownership` on (the default), a virtual-key passthrough request that reaches a tuning or customization collection is refused with 403, whatever its method, path spelling or passthrough route: OpenAI `fine_tuning` and `models/ft:...`, Azure `fine-tunes`, Gemini `tunedModels`, Vertex `tuningJobs` and Bedrock's customization, import, copy, deployment and provisioned-throughput collections. Inference is unchanged, and requests without a virtual key, or with the setting off, are not restricted
- **Method overrides are never forwarded to a provider** - `X-HTTP-Method-Override`, `X-HTTP-Method` and `X-Method-Override` (any case, `_` for `-`) are dropped from passthrough headers, `x-bf-eh-*` extra headers, allowlist direct forwarding and WebSocket forwarded headers, so an upstream that honours them cannot act on a different method than governance checked
- **A2A error text follows the content setting on export** - an Agent Gateway operation's error message, which is the upstream agent's own text and can repeat what it was sent, is no longer exported as the OTEL span status message when content logging is off for the profile or the virtual key; the span keeps its error status, `error.type` and task identity. The shared content-stripped trace copy that other connectors use withholds it the same way
- **Guardrail redaction reaches every typed input on a trace span** - a text-completion prompt, embedding text, speech input, speech instructions, transcription prompt and text-completion suffix are redacted on the span's typed record as well as on its attributes, so a connector reading the record no longer sees the original; the request itself is never edited
- **Passthrough parse diagnostics no longer quote bodies** - the debug line for a passthrough body that only partly parsed, or whose parse panicked, names the log row and the failure's type instead of the decoder error or panic value, which could quote request or response content (or an upstream error message) into the application log
- **The setup lock accepts scoped temp tokens only for their own route** - while the OSS setup lock is active, an MCP consent or per-user auth temp token authorizes exactly its method, path and resource, as it does once dashboard auth is on, without running as the admin; the flows no longer fail with 401 mid-consent
- **The outbound client factory starts on the reconciled proxy** - the proxy from config.json is applied to the stored global proxy before the client factory for webhooks, MCP, OAuth, catalog sync and other non-inference traffic is built, so that traffic no longer runs on the previous or absent proxy until the next dashboard edit
- **Agent card discovery keeps a registration's public-target restriction** - live card discovery for a registration created without authentication applies its persisted public-only restriction, as registration and runtime calls do, so an operator's private-network allowlist no longer lets it fetch a card from a private address
- **Stored A2A push configurations belong to the tenant that registered them** - the gateway's record of a client's push callback is keyed by agent, task and configuration ID without the tenant, so two tenants naming the same IDs replaced each other's callback and ingress token, and each could read, list or delete the other's. A request now reaches only the configurations its own tenant registered (a request naming no tenant is the empty tenant, not a wildcard), registering an ID another tenant holds for the task is refused with invalid params before any upstream call, and the store's upsert and the embedded-config bind never replace another tenant's row
- **Queued push deliveries stay with the registration that accepted them** - a delivery records the ingress token of the registration it was accepted for (new `registration_hash` column on the outbox); if that registration is deleted and the same agent/task/configuration is registered again, by any tenant, the queued payload is dead-lettered instead of being sent to the new callback. Rows queued before the column existed keep the previous behaviour
- **Two pushes racing to bind one pending embedded configuration cannot both queue** - the configuration is read back after the bind, and a push whose task the row is not bound to is refused rather than queued under another task's configuration
- **A security scheme that changed drops the credentials it no longer fits** - replacing an MCP OpenAPI document clears a stored credential whose same-named scheme moved location or type, or whose scheme was removed, so a key that moved to the query string is not sent in URLs; when the previous schemes cannot be compared, none is kept, and a toast says what was cleared
- **Agent log Delete acts on the selected operation** - a failed detail fetch shows the selected row's summary, so Delete can no longer remove the previously opened operation
- **Toggling an agent keeps its approved credential origins** - the enable and disable switch resends them with the rest of the registration, so re-enabling still reaches an approved runtime endpoint
- **A log hidden by an update loses the content it was saved with** - a request whose final decision hides content empties the row's input, output and other payload columns and its content summary in SQLite, Postgres and ClickHouse, where the row used to keep them under `content_hidden`; token usage and cache metadata stay for pricing
- **A request cannot finish another caller's log row** - request IDs are caller-supplied, so a request with no pending log entry reconciled onto any row carrying its ID; a late completion now applies only to a still-processing partial row of the key the request presented, enforced in the write itself on each store
- **A transcription session keeps what governance decided on its upgrade** - the session's model arrives after the WebSocket upgrade, by when the request is finished; its governance and routing values are now read before that, so a key restriction cannot be lost, and pre-request hook values no longer go to a recycled request
- **A case-variant `oauth_key_config` gets the unknown-field check** - the key write paths now check every spelling the decoder accepts, on create as well as update
- **A Cloudflare migration asks for the bare token when the whole header is a reference** - such a reference resolves to `Bearer <token>`, which the native provider would have sent as `Bearer Bearer <token>`

## 🐞 Fixed

- A proxy changed from one URL to another never reuses a tunnel through the old proxy; guarded HTTP transports close idle connections after 90 seconds
- MCP verification and instruction-refresh handshakes for an SSE client use SSE, so an SSE-only server no longer answers 405 and an edit no longer keeps stale instructions
- Image and document URL fetches through the environment proxy choose `HTTPS_PROXY` or `HTTP_PROXY` by the request's scheme rather than its port, and the provider auth and fetch clients keep each target's scheme only while a request needs it instead of for the life of the process
- A stream attempt whose connection stalls in DNS, dialing or the proxy handshake ends at its first-token deadline and moves to its fallback on time
- With config.json as the source of truth, an unchanged agent declaration is written again on every load, so an API edit to that agent is reverted as for other sections; split mode keeps the edit until the file changes
- While dashboard auth is disabled, an agent update that resends the stored credential origins unchanged is accepted; only a change to them needs dashboard auth
- The background queue reports a lease that lapsed because its renewals kept failing, and a claim that superseded an earlier claim of the same delivery on the same instance, as a lost lease (`queue: lease lost ...`) like every other lease loss; they used to log "lease lapsed" or nothing, so a redelivery after either looked like an unexplained duplicate
- `extra_headers` values in config.json and the Helm chart's `networkConfig` may be structured secret references (`{"type": "env", "ref": "env.VAR_NAME"}`), which the gateway already accepted
- A registration's push deliveries are delivered in the order they were accepted: a delivery is listed and claimable only while no earlier one for the same agent, task and configuration is still pending, checked in the claim statement itself so the order holds across relay instances, so an artifact append can no longer overtake the replacement it follows
- A JSON reply to an A2A streaming request that cannot be read, is larger than 1 MiB or is not JSON is returned as an error instead of an empty or truncated successful stream
- Two equal artifact-append events pushed by an upstream agent are both delivered (an append carries no event identity, so appends are at least once); every other event keeps its content-digest deduplication
- An agent registered with `enabled: false` stays disabled across a reload; the column default no longer turns an explicit false into true on create
- An Agent log update that lands before the log's initial object upload finished builds on the queued full payload, so the stored object keeps the untruncated bodies and raw fields; and a body update that also changes the row's status queues its upload under the new status instead of being dropped
- Fetching an agent card keeps OAuth settings the card does not describe (resource, discovery URL, provider URL) and the client credentials, and in manual mode a refetch shows the card without replacing the operator's configuration
- The Agent logs page keeps the history view when the 30-day probe is empty but the selected range has rows, and an explicit range keeps its date controls when empty
- The Agent session view assembles the artifacts of a streamed task snapshot instead of reading it as a status update
- Clicking the selected provider in a dashboard filter returns to All Providers, and the charts aggregate every provider again
- Expanding a session in the logs lists every member past the first page; a failed page collapses the session rather than showing part of it, and a reset stops the read
- An unchanged stored OpenAPI document keeps the URL it was read from when saved back, and its relative servers resolve against that URL in the preview
- Entity pickers start from the first page after a search is cleared, instead of reviving the offset left behind before it
- Model budgets accept names the catalog does not list, such as deployment aliases
- Warp follow-ups queued behind an answer survive the dock closing and send when it reopens, and a history load that lands after its panel unmounted no longer replaces a newer conversation
- A row whose insert the store dropped no longer counts as persisted billing, so a later richer duplicate still repairs the row that did land
- A duplicate-billing repair interrupted by shutdown is retried by the drain, and a wedged repair no longer holds shutdown past its deadline
- Log rows accepted before shutdown reach the store: Cleanup waits for admitted producers and for guardrail results already claimed, instead of closing the queue behind them
- A live session row keeps its input, output and additional cost split, so its cost breakdown adds up to its cost
- Merging duplicate log rows keeps the priced row's cost split and breakdown
- An injected-tool loop is priced one provider call at a time, on success, in streams and on errors, so turns of 150k input tokens no longer cross a 272k threshold together, and each turn keeps its own service tier, fallback model, per-request fee and provider-reported cost
- Responses that drain onto one live billing unit after a refused renewal are priced one by one, and a settled live response's service tier no longer prices the next one
- A request whose provider injects a tool is charged to its budgets: the tool call no longer replaces the limits the attempt answers to, or claims the inference's billing
- Decision answers OpenAI rejects carry the reported usage, and OpenRouter's carry its billed cost, so governance and logging charge them instead of recording them free
- A failed attempt's error stays off the trace's root span when a fallback succeeds: the root reports the final attempt's outcome when the trace ends, and never overwrites what the transport recorded there
- The token histogram on Postgres trims a window's partial boundary hours as the request histogram does, so a window opening or closing mid-hour counts only its own tokens, cached reads included
- A matview pass that skips views as recently refreshed no longer records the pending log activity as refreshed, so those writes reach the views on the next tick instead of waiting for the safety interval
- ClickHouse: expiry and stale-job sweeps delete every version of an async job, so an older version no longer comes back; a queue's acknowledged tombstone lives as long as its message, so a late retry cannot run a delivered message again; Warp conversation pruning bounds in milliseconds, so a stale thread with a fractional second is deleted
- A settings save no longer fails on what it did not change: a pricing, model-parameters or MCP-library URL equal to the stored one is not re-checked, so a `file://` or private URL from config.json stays usable, and a disabled MCP library sync (`mcp_library_sync_interval` 0) passes unchanged. A new URL, or turning the sync off over the API, is still refused
- The MCP client list carries `max_instructions_length`, so an edit from the dashboard no longer resets a client's instruction cap
- A provider key update honours the field names the decoder accepts: `{"Weight": 3}` applies instead of being replaced by the stored value, and the secret-reference and dial-target checks judge what was decoded
- OpenAPI MCP: `PUT` tools are marked destructive, so clients keep confirming a replacement; they stay idempotent, so the gateway's auth-failure retry treats them as before
- OpenAPI MCP: a hosted OpenAPI 3 document with `servers` absent or empty uses the default server at `/`, resolved against `$self` or its URL without the URL's credentials. An operation server at another origin keeps asking for a base URL
- OpenAPI MCP: keywords beside a 3.1 `$ref` follow the usual rules, so a default holding a `$ref` key or a property named `$ref` no longer costs the operation
- OpenAPI MCP: a body with an `allOf` that cannot be merged travels whole, with the required names it declares
- `max_instructions_length` in config.json reaches the stored client and its reconciliation hash, so a limit-only edit applies and other edits no longer reset it; an entry that leaves it out keeps its stored hash, and a negative value is refused
- A distributed lock holder stops at the expiry the store last confirmed, even while renewals hang or fail, and its release is bounded by that lease and leaves a row another holder has taken alone
- Upgrading from a release before v2.3.0 keeps dashboard settings when config.json is unchanged: the stored checkpoint is recognized and moved to the new hash format. A file that was edited, including one setting a field those releases never hashed, still wins
- The in-memory queue releases acknowledged messages on purge even when a consumer group has stopped claiming, instead of holding their payloads until the group's next claim
- The notification center's background jobs section shows loading and failure, with a retry, instead of "No background jobs" before the list arrives
